# How it works

## Boot

`boot.iso` is a GameCube disc image built by `tools/mkiso.py`:

- `0x0000` disc header: game ID `GCMEHB`, the GameCube magic, title, and at `0x420` the offset of the DOL.
- `0x0440` bi2 (region "any").
- `0x2440` apploader header and code (`apploader/apploader.c`, about 600 bytes).
- an ISO 9660 file system after the 32 KB system area (empty in the release; the emulator test disc carries a sample library here).
- the menu's DOL, appended at the end.

The console's IPL loads the apploader to `0x81200000` and calls it: the apploader asks for the header
word at `0x420`, then the DOL header, then each section straight to its load address, and returns the
entry point. GC Loader presents `/boot.iso` as the disc, so this is what the console runs at power on.

## Card access

libogc2 provides the disc interfaces: `__io_gcode` (GC Loader), `__io_gcsd2` (SD2SP2), `__io_gcsdb` /
`__io_gcsda` (SD Gecko), mounted with libfat under the same names Swiss uses for those devices
(`gcldr`, `sdc`, `sdb`, `sda`). The first one with `/games` wins. An ISO 9660 disc (`dvd`) is the last
resort; it is how the menu reads its sample library in Dolphin, which has no SD adapter for the GameCube.

## Handing a game to Swiss

Swiss reads its command-line arguments as lines of its settings file. Cube Menu starts Swiss's
`boot.dol` with one argument:

```
Autoload=gcldr:/games/F-Zero GX/game.iso
```

and Swiss boots that file at startup, with the game's own Swiss settings. Swiss is unmodified; nothing
of it is included in Cube Menu.

Starting a DOL from a running program (`source/boot.c`, `source/stub.S`):

1. read the DOL into a buffer that does not overlap any range the new program loads to;
2. unmount the card, shut the OS down (`SYS_ResetSystem(SYS_SHUTDOWN)`), disable interrupts;
3. write the command line right after the new program's BSS and the `__argv` block after its entry
   branch (devkitPPC programs carry the `_arg` magic there);
4. copy a small position-independent stub to `0x80002000`, with the list of copies to make;
5. the stub clears MSR[EE], copies every section, zeroes the BSS, writes back / invalidates the caches
   for each range, and jumps to the entry point.

`0x80001800` is avoided on purpose: emulators treat a jump there as "return to the loader".

## Rendering

GX with one vertex format (position, colour, texture coordinate). The 3D case is a box mapped from the
full cover (`back | spine | front`, the spine is 5% of the width), the floor reflection is the same case
mirrored under the floor with vertex alpha fading out. Lighting is a fixed key light computed per face
on the CPU. Text uses baked fonts (IA8 atlases generated by `tools/mkfont.py`).

## Clips

`clip.cmv`: a 32-byte header (`CMV1`, width, height, fps, frame count, frame size) followed by
fixed-size CMPR frames. A thread reads one frame per tick into one of three textures; the UI draws the
last complete one. No decoding on the console, 563 KB/s at 320x176 @ 20 fps.

## Play time

On launch the menu writes `pending=<ID>,<time>` to `cubemenu/stats.ini`. The next boot credits
`now - time` to that game when it is between 30 seconds and 12 hours, then clears it.
